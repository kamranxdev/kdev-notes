## 🪟 What is a Window Function?

Traditional `GROUP BY` clauses collapse individual table rows into summary groups. In contrast, **Window Functions** perform calculations across a subset of table rows (a partition) while **preserving the individual row identity and granularity** of the dataset.

* **Analogy**: *A sliding camera lens.* The lens focuses on a specific section of rows (the partition) to perform calculations (like computing running sums or department ranks), but outputs every original row alongside its calculated analytical value.

```sql
SELECT emp_name, dept_id, salary,
       AVG(salary) OVER(PARTITION BY dept_id) AS dept_avg_salary,
       RANK() OVER(PARTITION BY dept_id ORDER BY salary DESC) AS sal_rank
FROM employees;
```

## 📊 Ranking Functions: ROW_NUMBER vs RANK vs DENSE_RANK

When ranking items within a partition (e.g., top-earning employees per department), SQL provides three primary functions that handle tied values differently:

| Employee | Salary | `ROW_NUMBER()` | `RANK()` | `DENSE_RANK()` |
| :--- | :--- | :--- | :--- | :--- |
| **Alice** | $100,000 | 1 | 1 | 1 |
| **Bob** | $90,000 | 2 | 2 | 2 |
| **Charlie** | $90,000 | 3 | 2 | 2 |
| **David** | $80,000 | 4 | **4** (Leaves gap) | **3** (No gap) |

* `ROW_NUMBER()`: Assigns a strictly sequential unique integer to every row regardless of ties.
* `RANK()`: Assigns the same rank to tied rows, but **skips subsequent rank numbers** (gap left).
* `DENSE_RANK()`: Assigns the same rank to tied rows, but **does not skip rank numbers** (consecutive integers).

## ⏱️ Navigation & Framing Functions

### Navigation Functions
* `LAG(col, offset, default)`: Accesses column data from a previous row relative to the current row without doing a self-join (ideal for calculating Month-over-Month growth).
* `LEAD(col, offset, default)`: Accesses column data from a subsequent row.
* `FIRST_VALUE(col)` / `LAST_VALUE(col)`: Returns the first or last value in the specified window frame.

### Window Frame Specification (`ROWS / RANGE BETWEEN`)
Specifies the exact sliding boundary of rows included in the window calculation:

```sql
-- Calculate a 3-month moving average of sales revenue
SELECT sale_date, amount,
       AVG(amount) OVER (
           ORDER BY sale_date 
           ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
       ) AS moving_3m_avg
FROM monthly_sales;
```

* `UNBOUNDED PRECEDING`: Starts at the very first row of the partition.
* `CURRENT ROW`: Ends at the current row being processed.
* `UNBOUNDED FOLLOWING`: Extends to the final row of the partition.

## 💻 Practice Problems

<Problem title="Problem: Calculating Year-Over-Year Sales Growth">
<ProblemDescription>
Given a `yearly_revenue` table with columns `year` and `revenue`, write a SQL query to calculate each year's revenue, the previous year's revenue, and the YoY percentage growth rate.
</ProblemDescription>
<ProblemSolution>
Use the `LAG()` window function to retrieve the prior year's revenue:

```sql
SELECT year,
       revenue,
       LAG(revenue, 1) OVER (ORDER BY year) AS prior_year_revenue,
       ROUND(
           ((revenue - LAG(revenue, 1) OVER (ORDER BY year)) / 
            NULLIF(LAG(revenue, 1) OVER (ORDER BY year), 0)) * 100, 2
       ) AS yoy_growth_pct
FROM yearly_revenue;
```
</ProblemSolution>
</Problem>
