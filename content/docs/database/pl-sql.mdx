### 1. PL/SQL Architecture & Engine Context Switches

Imagine a bank manager (the **PL/SQL Engine**) and a database vault clerk (the **SQL Engine**).
*   The manager processes logic, runs loops, checks conditions, and writes instructions in a notebook.
*   The clerk can open vault drawers, read records, and write data to cards.
*   **Context Switch**: Every time the manager needs data, they must walk over to the clerk, explain the request, wait for the clerk to find the record, and walk back.

```
              ┌──────────────────────────────────────────────┐
              │              PL/SQL Block Input              │
              └──────────────────────┬───────────────────────┘
                                     ▼
                       ┌──────────────────────────────┐
                       │        PL/SQL Engine         │
                       │  (Runs Loops, Assignments)  │
                       └──────┬────────────────▲──────┘
                         SQL  │                │  SQL
                  Statements  │                │  Data
                              ▼                │
                       ┌───────────────────────┴──────┐
                       │          SQL Engine          │
                       │   (Runs SELECT, INSERT...)   │
                       └──────────────────────────────┘
```

> [!WARNING]
> If the manager runs a loop 10,000 times, walking back and forth to the clerk for a single folder each time (row-by-row fetching), this creates massive performance overhead. This is called a **row-by-row context switch bottleneck**.

### 2. Block Structures & Anchors

PL/SQL code is written in structured blocks.
*   **Scalar Anchoring (`%TYPE`)**: Copies the data type and constraints of a database column dynamically. *Analogy: Buying a key blank designed to copy a specific room key.*
*   **Record Anchoring (`%ROWTYPE`)**: Copies the structure of an entire table row dynamically. *Analogy: Cloning a master room layout card.*

```sql
DECLARE
  -- Copy type from employee name column
  v_name employees.first_name%TYPE;
  -- Copy structure of entire employee row
  v_emp_row employees%ROWTYPE;
BEGIN
  SELECT first_name INTO v_name FROM employees WHERE employee_id = 101;
END;
/
```

### 3. PL/SQL Collections & Records

Collections are PL/SQL's version of arrays or lookup tables:

*   **Associative Array (Index-by Table)**: A private dictionary address book in memory. Keys can be integers or strings.
*   **Nested Table**: A dynamic set of drawers. Starts uninitialized (`NULL`) and must be initialized using a constructor before use. It can grow indefinitely.
*   **Varray**: A rigid cardboard egg carton with a fixed number of slots. Must be initialized using a constructor and cannot exceed its declared capacity.

```sql
DECLARE
  -- Varray limited to 3 items
  TYPE type_phones IS VARRAY(3) OF VARCHAR2(15);
  v_list type_phones := type_phones('+1-555', '+1-777'); // Constructor
BEGIN
  v_list.EXTEND; // Allocate slot 3
  v_list(3) := '+1-999';
END;
/
```

### 4. Bulk Processing & Performance Optimization

To minimize the performance cost of context switches between the PL/SQL and SQL engines, use bulk operations:

#### BULK COLLECT (Efficient Fetching)
Instead of walking back and forth fetching rows one-by-one, the manager gives the clerk a large cart and says "go fetch all 500 folders in one trip."

```sql
DECLARE
  TYPE type_emp_tab IS TABLE OF employees%ROWTYPE;
  v_emps type_emp_tab;
BEGIN
  -- Fetch entire result set in a single context switch
  SELECT * BULK COLLECT INTO v_emps FROM employees WHERE department_id = 10;
END;
/
```

> [!TIP]
> Fetching millions of rows at once using `BULK COLLECT` can exhaust the database server's RAM. Use the `LIMIT` clause with explicit cursors to fetch data in manageable batches (typically 100 to 1000 rows at a time).

```sql
DECLARE
  CURSOR c_emps IS SELECT * FROM employees;
  TYPE type_emp_tab IS TABLE OF employees%ROWTYPE;
  v_batch type_emp_tab;
BEGIN
  OPEN c_emps;
  LOOP
    FETCH c_emps BULK COLLECT INTO v_batch LIMIT 100;
    EXIT WHEN v_batch.COUNT = 0;
    -- Process batch of 100
  END LOOP;
  CLOSE c_emps;
END;
/
```

#### FORALL (Efficient Writing)
Handing the clerk a stack of 500 update forms and saying "run all these updates in one go."

```sql
DECLARE
  TYPE type_id_list IS TABLE OF employees.employee_id%TYPE;
  v_ids type_id_list := type_id_list(101, 102, 103, 104);
BEGIN
  -- FORALL is not a loop; it is a batch instruction sent to the SQL engine
  FORALL i IN 1..v_ids.COUNT
    UPDATE employees 
    SET salary = salary * 1.05 
    WHERE employee_id = v_ids(i);
END;
/
```

### 5. Cursors: Pointer Light Beams

A cursor is a pointer to the result set of a query in the database.
*   **Analogy**: A laser pointer. Instead of carrying a 10-ton file cabinet into your office, you shine a laser pointer (cursor) on one folder at a time, reading it and moving to the next.
*   **Ref Cursor**: A portable laser pointer. You can create a query pointer and hand the laser pointer to another module or client application so they can read the rows themselves.

```sql
DECLARE
  -- Weak ref cursor (can point to any query structure)
  TYPE type_generic_cursor IS REF CURSOR;
  v_cursor type_generic_cursor;
  v_name employees.first_name%TYPE;
BEGIN
  OPEN v_cursor FOR SELECT first_name FROM employees WHERE department_id = 20;
  LOOP
    FETCH v_cursor INTO v_name;
    EXIT WHEN v_cursor%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(v_name);
  END LOOP;
  CLOSE v_cursor;
END;
/
```

### 6. Triggers & The Mutating Table Error

#### The Paradox of Pulling the Rug
*   **Mutating Trigger (ORA-04091)**: Imagine writing a rule: "Every time a chair is moved (row update), recount all chairs in the room to check the total count." But while the chair is mid-air (row-level trigger), the table state is unstable. Oracle throws a mutating error to prevent reading from a floor that is currently shaking.

#### The Solution: Compound Triggers
A compound trigger acts as a smart assistant who writes down notes on moved chairs in a notebook during the event, and only recounts the total room once everyone has finished moving chairs (statement-level end).

```sql
CREATE OR REPLACE TRIGGER trg_check_salary
FOR UPDATE OF salary ON employees
COMPOUND TRIGGER
  -- Private global collection to record updates
  TYPE type_id_list IS TABLE OF employees.employee_id%TYPE;
  v_updated_ids type_id_list := type_id_list();

  -- 1. Row-level: record the IDs, do NOT query the table
  AFTER EACH ROW IS
  BEGIN
    v_updated_ids.EXTEND;
    v_updated_ids(v_updated_ids.LAST) := :NEW.employee_id;
  END AFTER EACH ROW;

  -- 2. Statement-level: run checks after all updates complete
  AFTER STATEMENT IS
    v_total NUMBER;
  BEGIN
    -- Safe to query now that the table is stable
    SELECT SUM(salary) INTO v_total FROM employees;
    DBMS_OUTPUT.PUT_LINE('Total salary pool: ' || v_total);
  END AFTER STATEMENT;
END;
/
```

### 7. Autonomous Transactions: Separate Logbooks

By default, all DML operations in PL/SQL are part of the current transaction. If the main transaction rolls back, all updates roll back.
*   **Autonomous Transaction**: A separate, independent transaction block.
*   **Analogy**: A separate logbook. You open a new notebook, write down log entries, commit them, and close the book. Even if you rip up and burn the main transaction book later, the entries in the logbook remain safe.

```sql
CREATE OR REPLACE PROCEDURE log_error(p_msg VARCHAR2) IS
  PRAGMA AUTONOMOUS_TRANSACTION; // Instructs Oracle to run this independently
BEGIN
  INSERT INTO error_logs (log_msg, log_time) VALUES (p_msg, SYSDATE);
  COMMIT; // Commits ONLY the error log entry, does not affect main transaction
END;
/
```

### 9. Practice Problems

<Problem title="Problem 1: Batched Salary Updates">
<ProblemDescription>
Write a PL/SQL procedure that increases the salary of all employees in department `20` by 10%. Use explicit cursors and `BULK COLLECT` with a `LIMIT` of 100 to process updates in batches, avoiding memory exhaustion. Use `FORALL` to execute the updates.
</ProblemDescription>
<ProblemSolution>
This procedure combines batch fetching and bulk updates:

```sql
CREATE OR REPLACE PROCEDURE update_dept_salaries IS
  CURSOR c_emps IS 
    SELECT employee_id FROM employees WHERE department_id = 20;
    
  TYPE type_id_tab IS TABLE OF employees.employee_id%TYPE;
  v_ids type_id_tab;
BEGIN
  OPEN c_emps;
  LOOP
    -- 1. Fetch 100 IDs at a time
    FETCH c_emps BULK COLLECT INTO v_ids LIMIT 100;
    EXIT WHEN v_ids.COUNT = 0;
    
    -- 2. Execute updates in a single batch
    FORALL i IN 1..v_ids.COUNT
      UPDATE employees 
      SET salary = salary * 1.10 
      WHERE employee_id = v_ids(i);
      
    COMMIT; -- Commit batch transaction
  END LOOP;
  CLOSE c_emps;
END;
/
```
</ProblemSolution>
</Problem>
