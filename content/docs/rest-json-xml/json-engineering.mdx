## 🏛️ High-Level Concept Definition & Real-World Analogy

**JSON** (**JavaScript Object Notation**), standardized under **RFC 8259** and ECMA-404, is a text-based, language-independent data-interchange format. Derived from ECMAScript object literal syntax, JSON represents structured data using two universal data structures: key-value object mappings (`{}`) and ordered lists of values (`[]`). Because of its minimal syntax overhead, fast string lexical analysis, and native compatibility with browser execution environments, JSON replaced XML as the dominant serialization format for modern REST APIs, web applications, microservices, and NoSQL databases (e.g., MongoDB, PostgreSQL JSONB).

Under the hood, a JSON parser acts as a finite state automaton that processes incoming streams of UTF-8 or UTF-16 character sequences. The parser lexically scans characters into tokens (string literals, numeric literals, punctuation delimiters), builds an abstract syntax tree (AST) or token stream, and maps those tokens into runtime programming objects (such as Java `HashMaps`, `ArrayLists`, or strongly-typed POJOs). Understanding how JSON parsers parse text and manage heap memory is essential for building high-throughput, low-latency microservices.

### 🏙️ Real-World Analogy: Standardized Freight Cargo Shipping

To understand JSON syntax and parser internals, envision a **Standardized Freight Shipping System**:

*   **JSON Object (`{}`)**: A **Sectioned Cargo Container**. Keys are pre-printed, labeled slots inside the container (`"sku_id"`), and values are items placed inside those designated slots.
*   **JSON Array (`[]`)**: A **Conveyor Belt Grid**. An ordered, index-based row of items where each position (0, 1, 2) holds a distinct package.
*   **Double Quotes (`"key"`)**: Mandatory **Laser-Etched Metal Plates**. In JSON rules, every key tag *must* have laser-etched double quotes. Writing keys without quotes or with single quotes is like using temporary tape—the automated scanner will reject the container!
*   **Streaming Parser (`JsonParser`)**: An **Assembly Line Scanner**. Inspects packages one-by-one as they roll past on a belt, processing items instantly without storing the whole shipment in warehouse memory.
*   **Tree AST Parser (`ObjectMapper.readTree()`)**: A **Warehouse Blueprint Reconstruction**. Unpacks every item from the cargo container, builds a 3D structural model of the shipment on the warehouse floor, consuming significant space before allowing workers to read values.

## 📊 Quick Reference & Comparison Matrices

### 1. Native JSON Data Types Specification Matrix

| Data Type | Syntax Example | RFC 8259 Constraints & Edge Cases |
| :--- | :--- | :--- |
| **String** | `"name": "Alex\nMercer"` | Must be enclosed in **double quotes** (`""`). Supports Unicode escape sequences (`\u0020`). Single quotes (`''`) are **invalid**. |
| **Number** | `"price": 99.95`, `"exp": -4e2` | Base-10 integer or floating-point. No leading zeros allowed (`012` is invalid). `NaN`, `Infinity`, and `-Infinity` are **forbidden**. |
| **Boolean** | `"active": true` | Strictly lowercase `true` or `false`. Quoted string `"true"` is parsed as a String, **not** a Boolean. |
| **Null** | `"department": null` | Strictly lowercase `null`. Indicates missing or empty state. `undefined` is **invalid**. |
| **Object** | `{"k1": "v1", "k2": "v2"}` | Unordered collection of key-value pairs enclosed in `{}`. Keys **must** be double-quoted strings. |
| **Array** | `["Java", 42, true]` | Ordered list of zero or more values enclosed in `[]`. Heterogeneous data types allowed. |

## ⚡ Architectural Deep-Dive & Engineering Concepts

### 1. Valid vs. Invalid JSON Syntax Edge Cases

```json
// -------------------------------------------------------------
// 1. VALID JSON (Adheres strictly to RFC 8259)
// -------------------------------------------------------------
{
  "employeeId": 1088,
  "fullName": "Alex Mercer",
  "isRemote": true,
  "roles": ["Admin", "Architect"],
  "metadata": null,
  "score": 98.6
}

// -------------------------------------------------------------
// 2. INVALID JSON (Will trigger Lexical Parsing Exception)
// -------------------------------------------------------------
{
  'employeeId': 1088,           // ❌ ERROR 1: Single quotes used for key!
  fullName: "Alex Mercer",      // ❌ ERROR 2: Unquoted key!
  "isRemote": True,             // ❌ ERROR 3: Capitalized "True"! Must be lowercase "true".
  "roles": ["Admin", "Architect",], // ❌ ERROR 4: Trailing comma after "Architect"!
  "status": undefined,          // ❌ ERROR 5: "undefined" is invalid JSON!
  "score": NaN,                 // ❌ ERROR 6: "NaN" is invalid JSON!
  // This is a comment          // ❌ ERROR 7: Comments are strictly FORBIDDEN in RFC 8259!
}
```

<Callout type="error">
**The #1 JSON Parsing Trap: Trailing Commas & Single Quotes**  
JavaScript allows trailing commas (`[1, 2, 3,]`) and single-quoted object keys (`{'key': 'val'}`). **JSON RFC 8259 strictly forbids both!** Standard Java JSON parsers (like Jackson or `org.json`) will throw a `JsonParseException` immediately upon encountering single quotes or trailing commas.
</Callout>

### 2. Streaming Parser vs. AST Tree Parser Mechanics

Understanding memory allocation between **Streaming** and **AST Tree** parsing is critical for enterprise applications handling large payloads:

```
Stream Byte Payload (100 MB JSON File)
   │
   ├──────► AST Tree Parsing (JSONObject / ObjectMapper.readTree())
   │        Loads all 100 MB into memory as nested Java Objects (HashMap/ArrayList).
   │        Total Heap Memory Occupied: ~350 MB to 500 MB! Risk of OutOfMemoryError!
   │
   └──────► Streaming Tokenizer Parsing (Jackson JsonParser)
            Reads token-by-token (START_OBJECT -> FIELD_NAME -> VALUE_STRING).
            Discards tokens immediately after reading target field.
            Total Heap Memory Occupied: ~8 KB! Constant O(1) Memory!
```

### 3. Production Java Parsing Implementations

#### Pattern A: Manual Manipulation via `org.json`

```java
import org.json.JSONArray;
import org.json.JSONObject;

public class JSONOrgDemo {
    public static void main(String[] args) {
        String jsonText = "{"
                + "\"company\": \"TechCorp\","
                + "\"employees\": ["
                + "  {\"id\": 101, \"name\": \"Darshan\", \"salary\": 85000},"
                + "  {\"id\": 102, \"name\": \"Priya\"}"
                + "]"
                + "}";

        JSONObject root = new JSONObject(jsonText);
        String companyName = root.getString("company");

        JSONArray employees = root.getJSONArray("employees");
        for (int i = 0; i < employees.length(); i++) {
            JSONObject emp = employees.getJSONObject(i);
            String name = emp.getString("name");
            
            // USE optDouble / optInt TO AVOID JSONException ON MISSING KEYS!
            double salary = emp.optDouble("salary", 50000.0);
            
            System.out.println("Employee: " + name + " | Salary: $" + salary);
        }
    }
}
```

#### Pattern B: Data Binding via Jackson `ObjectMapper`

```java
import com.fasterxml.jackson.annotation.JsonIgnoreProperties;
import com.fasterxml.jackson.databind.ObjectMapper;

// Target POJO Class
@JsonIgnoreProperties(ignoreUnknown = true) // Prevents failure on extra unknown fields
class Employee {
    private int id;
    private String name;

    // Default constructor required for Jackson reflection
    public Employee() {}

    public int getId() { return id; }
    public void setId(int id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}

public class JacksonDemo {
    public static void main(String[] args) throws Exception {
        ObjectMapper mapper = new ObjectMapper();
        String jsonInput = "{\"id\": 101, \"name\": \"Darshan\", \"extra_field\": \"ignored\"}";

        // Deserialization: JSON -> Java POJO Instance
        Employee emp = mapper.readValue(jsonInput, Employee.class);
        System.out.println("Parsed Employee Name: " + emp.getName());

        // Serialization: Java POJO -> JSON String
        String jsonOutput = mapper.writerWithDefaultPrettyPrinter().writeValueAsString(emp);
        System.out.println("Serialized JSON:\n" + jsonOutput);
    }
}
```

<Callout type="tip">
**Use `optString()` and `@JsonIgnoreProperties` to Prevent Production Crashes**  
`JSONObject.getString("key")` throws a runtime `JSONException` if `"key"` is missing or `null`. Always use `optString("key", "default_value")` when parsing dynamic payloads. In Jackson, always annotate POJOs with `@JsonIgnoreProperties(ignoreUnknown = true)` to ensure your service doesn't crash when partner APIs add new response fields!
</Callout>

<Problem title="Problem: Parsing Nested JSON Arrays in Java">
<ProblemDescription>
Write a Java program using `org.json` to parse the following JSON response and compute the total sum of all item prices inside the `"cart"` array:

```json
{
  "store": "TechMart",
  "cart": [
    { "item": "Keyboard", "price": 45.50 },
    { "item": "Mouse", "price": 25.00 },
    { "item": "Monitor", "price": 220.00 }
  ]
}
```
</ProblemDescription>
<ProblemSolution>
Extract the `"cart"` `JSONArray`, iterate over each item object, and aggregate the `"price"` values using `optDouble`:

```java
import org.json.JSONArray;
import org.json.JSONObject;

public class CartSumCalculator {
    public static void main(String[] args) {
        String jsonPayload = "{"
                + "\"store\": \"TechMart\","
                + "\"cart\": ["
                + "  { \"item\": \"Keyboard\", \"price\": 45.50 },"
                + "  { \"item\": \"Mouse\", \"price\": 25.00 },"
                + "  { \"item\": \"Monitor\", \"price\": 220.00 }"
                + "]"
                + "}";

        JSONObject root = new JSONObject(jsonPayload);
        JSONArray cart = root.getJSONArray("cart");

        double totalPrice = 0.0;

        for (int i = 0; i < cart.length(); i++) {
            JSONObject itemObj = cart.getJSONObject(i);
            double price = itemObj.optDouble("price", 0.0);
            totalPrice += price;
        }

        System.out.println("Store: " + root.getString("store"));
        System.out.println("Total Cart Value: $" + totalPrice); // Output: $290.5
    }
}
```
</ProblemSolution>
</Problem>
