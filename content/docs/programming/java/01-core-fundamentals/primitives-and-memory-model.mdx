### 1. Primitive vs. Reference Types

Java divides data types into two distinct categories:

*   **Primitives**: Store the actual raw data value directly in the memory location allocated on the stack (or inside an object on the heap).
*   **References**: Store a memory pointer address pointing to an object instance residing on the Heap.

| Type | Bit Size | Default Value | Range / Memory Allocation | Analogy |
| :--- | :--- | :--- | :--- | :--- |
| `byte` | 8 bits | `0` | -128 to 127 | A tiny storage box |
| `short` | 16 bits | `0` | -32,768 to 32,767 | A medium drawer |
| `int` | 32 bits | `0` | -2.14B to 2.14B | A standard filing cabinet |
| `long` | 64 bits | `0L` | Very large integers (requires `L` suffix) | A shipping container |
| `float` | 32 bits | `0.0f` | ~7 decimal digits precision (requires `f` suffix) | Standard measuring cup |
| `double`| 64 bits | `0.0` | ~15 decimal digits precision | High-precision scale |
| `char` | 16 bits | `\u0000` | Single 16-bit Unicode character (e.g., `'A'`) | A single letter stamp |
| `boolean`| ~1 bit | `false` | `true` or `false` | A simple light switch |
| `Object`| 32/64 bits| `null` | Memory address pointer (points to the Heap) | A key containing a room number |

### 2. Class Fields vs. Local Variables

```java
class Account {
    int balance; // Instance field: automatically initialized to 0 on Heap creation
    
    void calculateInterest() {
        int rate; // Local variable: stored on Stack frame. NO DEFAULT VALUE!
        // System.out.println(rate); // COMPILE ERROR: Variable 'rate' might not have been initialized
    }
}
```

*   **Instance Fields**: When an object is instantiated on the heap, the JVM zeroes out memory, automatically initializing fields to default values (`0`, `0.0`, `false`, `null`).
*   **Local Variables**: Declared within methods and allocated on thread execution stack frames. **Local variables do not receive default values**. Referencing an uninitialized local variable causes a compilation error.

### 3. Wrapper Classes & Autoboxing

Java provides object wrappers for every primitive type (`Integer`, `Double`, `Boolean`, etc.) to allow primitives to be used in generic collections (`List<Integer>`).

*   **Autoboxing**: Automatic conversion of primitive values to wrapper objects (e.g., `int` -> `Integer.valueOf(10)`).
*   **Unboxing**: Automatic extraction of primitive values from wrapper objects (e.g., `Integer` -> `int`).

> [!WARNING]
> Unboxing a `null` wrapper reference (e.g. `Integer val = null; int num = val;`) throws a `NullPointerException` at runtime because `.intValue()` is invoked on `null`.

### 4. The Integer Cache Pool

To save memory and boost performance, Java pre-allocates an internal object cache for `Integer` instances in the range **`-128` to `127`**.

```java
Integer a = 100;
Integer b = 100;
System.out.println(a == b); // Prints: true (both variables reference the same cached object)

Integer c = 200;
Integer d = 200;
System.out.println(c == d); // Prints: false (outside cache range; == compares memory addresses)
System.out.println(c.equals(d)); // Prints: true (equals compares underlying primitive values)
```

`127` is within the standard Integer Cache range (`-128` to `127`), so `x` and `y` reference the exact same cached object in memory.
