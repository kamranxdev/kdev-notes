### 1. GC Reachability & Roots

The JVM Garbage Collector identifies unreachable objects using **Tracing Collector Algorithms** starting from **GC Roots**.

**GC Roots include**:
*   Active local variables and parameters on JVM Stack frames.
*   Loaded static fields in Metaspace.
*   Active JNI native memory pointers.

If an object on the Heap has no valid reference path connecting back to a GC Root, it is marked as garbage and reclaimed.

### 2. The Generational Hypothesis

Most objects in Java are short-lived ("die young"). Memory is divided into generations:

```
  ┌──────────────────────────────────────────────┬─────────────────────────────┐
  │                 Young Gen                    │           Old Gen           │
  │ ┌──────────────┬──────────────┬────────────┐ │ ┌─────────────────────────┐ │
  │ │ Eden Space   │ Survivor S0  │Survivor S1 │ │ │ Long-lived Objects      │ │
  │ └──────────────┴──────────────┴────────────┘ │ └─────────────────────────┘ │
  └──────────────────────────────────────────────┴─────────────────────────────┘
```

1.  **Eden Space**: New objects are initially allocated here.
2.  **Survivor Spaces (S0 / S1)**: Objects that survive a Minor GC are copied between S0 and S1, incrementing their **tenuring age**.
3.  **Old Generation**: Objects exceeding the tenuring threshold (e.g., age 15) are promoted to Old Gen.

---

### 3. Collector Algorithms Comparison

| Garbage Collector | Philosophy & Mechanics | Target Use Case |
| :--- | :--- | :--- |
| **Serial GC** (`-XX:+UseSerialGC`) | Single-threaded stop-the-world collector | Single-core embedded devices |
| **Parallel GC** (`-XX:+UseParallelGC`) | Multi-threaded throughput-focused collector | Batch processing workloads |
| **G1 GC** (`-XX:+UseG1GC`) | Region-based collector; cleans dirtiest regions first | Default general-purpose collector |
| **ZGC** (`-XX:+UseZGC`) | Ultra low-latency concurrent collector (pauses < 1ms) | High-frequency trading & microservices |
