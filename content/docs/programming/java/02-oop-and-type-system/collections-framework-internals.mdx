### 2. Lists: ArrayList vs. LinkedList

*   **ArrayList**: Backed by a contiguous dynamic array.
    *   *Access*: `O(1)` random access by index.
    *   *Insertion/Deletion*: `O(n)` amortized due to element shifting.
    *   *Resizing Math*: Expands by 50% (`1.5x`) when capacity limit is reached:
        `int newCapacity = oldCapacity + (oldCapacity >> 1);`
*   **LinkedList**: Implemented as a doubly-linked list.
    *   *Access*: `O(n)` sequential traversal.
    *   *Insertion/Deletion*: `O(1)` once position reference is obtained.

### 3. HashMap Internals & Hashing Math

HashMap stores key-value entries in an array of bucket nodes.

```
                  HashMap Bucket Structure
  ┌────────────────────────────────────────────────────────┐
  │ Hash Index = (n - 1) & hash(key)                      │
  │ [Bucket 0] ──► Node1(K,V) ──► Node2(K,V)               │
  │ [Bucket 1] ──► null                                    │
  │ [Bucket 2] ──► Red-Black Tree (if bucket has > 8 nodes)│
  └────────────────────────────────────────────────────────┘
```

1.  **Index Calculation**:
    Uses bitwise AND with array capacity `n` (always a power of 2):
    `int index = (n - 1) & hash(key);`
2.  **Bucket Collisions**: Colliding keys map to a singly-linked list in the target bucket.
3.  **Treeification Threshold**: If a single bucket's linked list length exceeds `8` (`TREEIFY_THRESHOLD`) and total table capacity is at least `64`, the bucket is converted from a linked list into a **Red-Black Tree**, reducing lookup time complexity from `O(n)` to `O(log n)`.

---

### 4. ConcurrentHashMap Thread Safety

Unlike `Hashtable` or `Collections.synchronizedMap` which lock the entire table, `ConcurrentHashMap`:

*   Uses **Compare-And-Swap (CAS)** instructions for non-blocking writes to empty buckets.
*   Synchronizes only the **head node** of a specific bucket during collision handling, allowing concurrent reads and writes across different buckets.
